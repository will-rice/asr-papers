# Introduction

Traditionally, <span acronym-label="ASR" acronym-form="singular+short">ASR</span> systems rely on hand-crafted feature extraction methods such as log Mel filterbank, <span acronym-label="MFCC" acronym-form="singular+short">MFCC</span> or Gammatone features . The advance of neural modeling in ASR raised the question whether feature extraction should rather be a part of the neural <span acronym-label="AM" acronym-form="singular+short">AM</span>. This could avoid potential information loss which might result in suboptimal performance. Besides some early methods using <span acronym-label="FFNN" acronym-form="plural+short">FFNNs</span> , mainly convolutional approaches have been proposed. They seem especially suitable for this task as they can operate similar to previous feature extraction methods but take advantage of learnable filters . In , the authors propose to use parameterized sinc functions to implement band-pass filters with few parameters in a way that is easy to interpret.

Recently, one line of research on learnable features for <span acronym-label="ASR" acronym-form="singular+short">ASR</span> focused on architectures which can be pre-trained on audio-only data in an unsupervised fashion . Untranscribed audio data is easier to obtain and the pre-training enables exploiting data which could otherwise not be incorporated. This is shown to be helpful in multiple cases, especially for low resource languages . Yet, it remains unclear whether these approaches offer additional benefits for research tasks with a closed set of training data. Additionally, none of these features has been tested with a hybrid <span acronym-label="NN" acronym-form="singular+short">NN</span>/<span acronym-label="HMM" acronym-form="singular+short">HMM</span> system beyond basic <span acronym-label="CTC" acronym-form="singular+short">CTC</span> to the best of our knowledge.

While lots of different architectures for <span acronym-label="ASR" acronym-form="singular+short">ASR</span> systems have been emerging in recent years , hybrid <span acronym-label="NN" acronym-form="singular+short">NN</span>/<span acronym-label="HMM" acronym-form="singular+short">HMM</span> systems constitute the state-of-the-art on many tasks like TED-LIUM release 2 , or AMI and achieve competitive results on LibriSpeech . It is therefore worthwhile to investigate how they can be further improved and how they compare to other high performance systems. This work aims at investigating and comparing the usefulness of different features – including learnable ones – for hybrid <span acronym-label="NN" acronym-form="singular+short">NN</span>/<span acronym-label="HMM" acronym-form="singular+short">HMM</span> systems. Besides using a pre-trained <span acronym-label="FE" acronym-form="singular+short">FE</span>, we explore how a strong existing <span acronym-label="AM" acronym-form="singular+short">AM</span> trained with different features on the same task can be exploited to reduce the training effort needed in order to deploy the new front-end. In the same way, are integrated to retrofit the system with speaker adaptation.

The feature extraction methods used in this work as well as some considerations regarding the hybrid <span acronym-label="ASR" acronym-form="singular+short">ASR</span> systems are presented in <a href="#sec:methods" data-reference-type="ref" data-reference="sec:methods">2</a>. The experiments are described in <a href="#sec:experiments" data-reference-type="ref" data-reference="sec:experiments">3</a> and discussed in <a href="#sec:results" data-reference-type="ref" data-reference="sec:results">4</a>. <a href="#sec:conclusions" data-reference-type="ref" data-reference="sec:conclusions">5</a> concludes the paper.

# Methods

## Feature Extraction

In the following, the feature extraction methods used in this work are explained. Note that for traditional hand-crafted feature extraction methods, there is a clear border between the <span acronym-label="FE" acronym-form="singular+short">FE</span> and the subsequent <span acronym-label="AM" acronym-form="singular+short">AM</span>, as depicted in <a href="#fig:fe_am" data-reference-type="ref" data-reference="fig:fe_am">[fig:fe_am]</a>. If the neural network operates directly on the audio samples, this border blurs. Nevertheless, for the sake of clarity, we refer to the layers that replace the hand-crafted feature extraction as <span acronym-label="FE" acronym-form="singular+short">FE</span> and to the remaining layers which are unchanged as <span acronym-label="AM" acronym-form="singular+short">AM</span>.

### Gammatone Features

Gammatone features are based on the Gammatone filter which is designed to mimic the human auditory filter. They were first introduced for large vocabulary <span acronym-label="ASR" acronym-form="singular+short">ASR</span> in . After pre-emphasizing the speech signal, a filterbank of Gammatone filters with center frequencies sampled from the Greenwood function is applied. Temporal integration of the filter outputs’ absolute values is typically performed using a Hanning window of 25 ms width with 10 ms shifts. After $`10^{th}`$ root compression, a cepstral decorrelation using the <span acronym-label="DCT" acronym-form="singular+short">DCT</span> and normalization techniques are applied.

### Supervised Convolutional Features

The described Gammatone feature extraction pipeline motivated the approach in . First, a convolutional layer for the purpose of <span acronym-label="tf" acronym-form="singular+short">tf</span> decomposition is applied on the raw waveform. In contrast to other works which train acoustic models directly on the waveform, the following envelope extraction is not performed by non-parameterized function such as max pooling, but rather with a rectification followed by low-pass filters which are shared between <span acronym-label="tf" acronym-form="singular+short">tf</span> filters. By introducing multiple ($`N`$) low-pass filters, a multi-resolutional processing can be achieved. Finally, an additional non-linearity, e.g. logarithmic or root compression, may be applied, and the resulting features can be interpreted as critical band energies. Since the convolutional layers of this method are trained supervised, we refer to the features as <span acronym-label="SC" acronym-form="singular+short">SC</span> features. The architecture is shown in <a href="#fig:mres_wav2vec" data-reference-type="ref" data-reference="fig:mres_wav2vec">[fig:mres_wav2vec]</a> (a).

### wav2vec Features

The wav2vec features were first introduced in and aim at learning audio representations in an unsupervised fashion from unlabeled data. These representations are supposed to improve downstream <span acronym-label="ASR" acronym-form="singular+short">ASR</span> performance. The network architecture consists of an encoder and a context network. A regular model with 5 layers in the encoder and 9 layers in the context network as well as a large model with 7 and 12 layers respectively were presented. All convolutional layers have 512 channels and use the activation function. In the encoder, skip connections are used to allow for better convergence of the large model. The output of the context network can be used as input to the <span acronym-label="ASR" acronym-form="singular+short">ASR</span> system. <a href="#fig:mres_wav2vec" data-reference-type="ref" data-reference="fig:mres_wav2vec">[fig:mres_wav2vec]</a> (b) depicts the model.

A contrastive loss is used as the objective during unsupervised pre-training. As no pre-training is conducted in this work, we refrain from giving the details. There have been follow up works using quantization and self-attention , however, we focus on the fully convolutional version.

## Hybrid ASR Systems

The <span acronym-label="ASR" acronym-form="singular+short">ASR</span> experiments in this work are carried out using hybrid <span acronym-label="NN" acronym-form="singular+short">NN</span>/<span acronym-label="HMM" acronym-form="singular+short">HMM</span> systems. We take the model described in as the baseline for our work and use the same <span acronym-label="CDp" acronym-form="plural+short">CDps</span> and the same alignments. The <span acronym-label="AM" acronym-form="singular+short">AM</span> architecture consists of 6 <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span> layers with 1000 units for each direction followed by a linear layer with softmax activation which maps to the 12001 <span acronym-label="CDp" acronym-form="singular+short">CDp</span> labels clustered by a <span acronym-label="CART" acronym-form="singular+short">CART</span> .

In , all <span acronym-label="AM" acronym-form="plural+short">AMs</span> trained with the frame-wise <span acronym-label="CE" acronym-form="singular+short">CE</span> loss were trained from scratch, i.e., the network parameters were initialized randomly at the beginning of the training. However, if a pre-trained model is already available, its parameters may be used in the same way a pre-trained <span acronym-label="FE" acronym-form="singular+short">FE</span> is used. This can reduce the training effort needed for deploying a new set of features.

A possible example of how to exploit this is presented in , where the goal is to obtain noise invariant features. A model trained on clean data is virtually divided into <span acronym-label="FE" acronym-form="singular+short">FE</span> and classifier by grouping lower and upper layers. Then, the model is further trained on noisy data while keeping the classifier constant or updating its parameters with a small learning rate. The learning rate for the <span acronym-label="FE" acronym-form="singular+short">FE</span> is not reduced and its parameters are either initialized randomly or from the clean model.

In this work, we use the best model obtained by frame-wise <span acronym-label="CE" acronym-form="singular+short">CE</span> training in as a baseline to use the parameters of the <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span> layers as well as the softmax output layer and continue training the model after resetting the learning rate. The baseline model was trained with 50-dimensional Gammatone features. If the dimension of the features differs from this, the first layer’s parameters can not be used because the weight matrix has a different shape. We circumvent this by initializing the first layer randomly and only adopt the parameters of the subsequent layers. Optionally, a random initialization of further subsequent layers may be applied. Unlike , we update all parameters with the same learning rate.

While most experiments are done using the frame-wise <span acronym-label="CE" acronym-form="singular+short">CE</span> loss, we also deploy a lattice-based version of the <span acronym-label="sMBR" acronym-form="singular+short">sMBR</span> criterion to conduct sequence discriminative training. The lattices are created using the frame-wise <span acronym-label="CE" acronym-form="singular+short">CE</span>-trained system. Then, we reset the learning rate and continue training now using the <span acronym-label="sMBR" acronym-form="singular+short">sMBR</span> criterion and an additional <span acronym-label="CE" acronym-form="singular+short">CE</span> smoothing. Note that this learning rate reset and continued training resembles the procedure described above. However, none of the <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span> layers is initialized randomly.

## Language Models

During recognition, the official 4-gram <span acronym-label="LM" acronym-form="singular+short">LM</span> as well as a custom <span acronym-label="LSTM" acronym-form="singular+short">LSTM</span> <span acronym-label="LM" acronym-form="singular+short">LM</span> are used in the first pass decoding . Additionally, the lattices are rescored utilizing a Transformer <span acronym-label="LM" acronym-form="singular+short">LM</span> . The <span acronym-label="LSTM" acronym-form="singular+short">LSTM</span> <span acronym-label="LM" acronym-form="singular+short">LM</span> consists of a linear layer followed by two <span acronym-label="LSTM" acronym-form="singular+short">LSTM</span> layers while the Transformer <span acronym-label="LM" acronym-form="singular+short">LM</span> is built by 96 layers with 8 attention heads and both have an output softmax layer over the full 200k vocabulary. Both are identical with the ones used in . The perplexities can be found in <a href="#tab:perplexities" data-reference-type="ref" data-reference="tab:perplexities">[tab:perplexities]</a>.

# Experiments

The experiments carried out for this work are presented in the following section. As in , the RWTH open-source toolkits RASR and RETURNN[^1] were used for training and recognition.

## LibriSpeech Dataset

The experiments are carried out on LibriSpeech which contains English read speech sampled at 16 kHz. Both the supervised <span acronym-label="ASR" acronym-form="singular+short">ASR</span> training as well as the unsupervised pre-training in are done on the 960 hours training data, so no external data was used for the wav2vec features. The <span acronym-label="LM" acronym-form="plural+short">LMs</span> are trained on the transcriptions of the 960 hours as well as the additional 800M-word text-only data. Testing is done on the common , , and subsets.

## Features

All features are extracted from the raw waveform inside RETURNN. This allows for an easy integrability but also makes the feature extraction a fully differentiable part of the neural network which can be helpful in case the <span acronym-label="ASR" acronym-form="singular+short">ASR</span> system is integrated with neural pre-processing steps such as speech separation or enhancement.

For the Gammatone features, we therefore apply a convolutional layer with 50 Gammatone filters and a size of 640 samples which corresponds to 40 ms. This is in contrast to the Gammatone feature extraction in , where RASR is used to extract Gammatone features and an implementation using <span acronym-label="IIR" acronym-form="singular+short">IIR</span> filters is deployed. The remaining steps are carried out as described in <a href="#sec:gammatone" data-reference-type="ref" data-reference="sec:gammatone">2.1.1</a>. Finally, we deploy batch normalization.

For the supervised convolutional features, we apply 150 filters for the <span acronym-label="tf" acronym-form="singular+short">tf</span> decomposition each with a size of 256 samples and a stride of 10 and take the absolute values of the outputs. The envelope extraction is performed by 5 filters with a size of 40 samples and a stride of 16. After taking the root of the absolute values, a layer normalization completes the feature extraction.

The wav2vec features are extracted as described in . We adapt the architecture denoted as *Large* in the original work, i.e., a convolutional encoder network consisting of 7 layers and a convolutional context network of 12 layers are used. The resulting features are 512-dimensional. Parameters of pre-trained models were made available by the authors and we use them in our experiments. As stated before, the pre-training was conducted on the LibriSpeech training data and no additional untranscribed audio data was used. The unsupervised pre-training is not subject of this work, however, we continue training the parameters using the supervised loss during <span acronym-label="ASR" acronym-form="singular+short">ASR</span> training.

<a href="#tab:training" data-reference-type="ref" data-reference="tab:training">[tab:training]</a> summarizes these features and outlines that while the Gammatone features are always extracted with a fixed set of parameters, the parameters of the supervised convolutional features can be updated during the supervised training and the wav2vec model can additionally even be pre-trained in an unsupervised fashion. Additionally, we can observe that the number of parameters for Gammatone and supervised convolutional features is comparable, while the wav2vec architecture exceeds this by a large factor. Note that the number of parameters for the Gammatone feature extraction is based on the <span acronym-label="FIR" acronym-form="singular+short">FIR</span> implementation described above.

The subsampling in the wav2vec encoder is chosen such that a feature frame is obtained every 10 ms which corresponds to the frame rate typically used for Gammatone features, e.g. in . This is convenient for training the hybrid <span acronym-label="ASR" acronym-form="singular+short">ASR</span> system with the frame-wise <span acronym-label="CE" acronym-form="singular+short">CE</span> criterion as the alignments obtained using Gammatone features can still be used. Additionally, it facilitates frame-wise feature combination. One frame of the wav2vec features in the regular model has a total receptive field of about 210 ms whereas it increases to about 810 ms for the large model. This is significantly larger than for the convolutional implementation of the Gammatone features or the features of the supervised convolutional approach, where the total receptive field corresponds to about 65 ms or 40 ms of audio, respectively.

When comparing different features, it seems natural to apply feature combination for possible further improvements. This is done using a frame-wise concatenation of all features here. The are computed per utterance, therefore, this single vector is repeated and concatenated in each frame.

# Experimental Results

## Effect of Training Strategies

The effect of performing unsupervised pre-training of the wav2vec features is shown in <a href="#tab:unsupervised" data-reference-type="ref" data-reference="tab:unsupervised">[tab:unsupervised]</a>. The experiment with 0 epochs of unsupervised pre-training corresponds to the case where the wav2vec model is initialized randomly and only updated in supervised training. We can observe that it helps to use pre-training even in a setting where no additional untranscribed data is used. However, the relative gains are smaller than the ones on <span acronym-label="WSJ" acronym-form="singular+short">WSJ</span> in when using additional data which is intuitive.

In the baseline model of , the pre-extracted input sequence of Gammatone features is split into chunks using a windowing process during mini-batch construction to speed up the training. The window comprises 50 frames and is shifted by 25 frames, which corresponds to 0.5 s and 0.25 s of the input signal, respectively. A collection of chunks obtained by this windowing process then makes up one mini-batch. Now, since the network input is the raw waveform, we perform chunking on the audio directly. As described in <a href="#sec:wav2vec" data-reference-type="ref" data-reference="sec:wav2vec">2.1.3</a>, the total receptive field of the wav2vec large model is about 810 ms, which exceeds the chunk size of 0.5 s. Therefore, chunking was performed with a size of 3 s and a shift of 1.5 s for our experiments in <a href="#tab:unsupervised" data-reference-type="ref" data-reference="tab:unsupervised">[tab:unsupervised]</a>. We observed, however, that reducing it to a size of 1 s and a shift of 0.5 s reduced the training time by about 25% while sacrificing only 0.1% absolute in <span acronym-label="WER" acronym-form="singular+short">WER</span> which is why we apply this setting for the subsequent experiments.

<a href="#tab:pretraining" data-reference-type="ref" data-reference="tab:pretraining">[tab:pretraining]</a> depicts the effect of using a pre-trained <span acronym-label="AM" acronym-form="singular+short">AM</span>. We use the baseline from which was trained for 12.5 epochs and train for 8 additional epochs here. Consistent improvements across all features can be seen. The parameters of the pre-trained <span acronym-label="AM" acronym-form="singular+short">AM</span> are exploited as described in <a href="#sec:hybrid_am" data-reference-type="ref" data-reference="sec:hybrid_am">2.2</a> and only the first <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span> layer is initialized randomly. Random initialization of further <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span> layers resulted in inferior performance.

## Comparison of Architectures

As observed in <a href="#tab:pretraining" data-reference-type="ref" data-reference="tab:pretraining">[tab:pretraining]</a>, the performance of the <span acronym-label="ASR" acronym-form="singular+short">ASR</span> system using wav2vec features is on par with the baseline in when training the <span acronym-label="AM" acronym-form="singular+short">AM</span> from scratch as well as with a pre-trained <span acronym-label="AM" acronym-form="singular+short">AM</span>. This proves the features’ suitability for hybrid systems. Similarly, the supervised convolutional features’ performance is in the same ballpark, although slightly worse when using the pre-trained <span acronym-label="AM" acronym-form="singular+short">AM</span>. The gap compared to the Gammatones matches the degradation of 3-4% relative found in for <span acronym-label="FFNN" acronym-form="singular+short">FFNN</span>. However, the results using an <span acronym-label="LSTM" acronym-form="singular+short">LSTM</span> back-end were significantly worse in which we do not observe here. A possible explanation is that the front-end parameters were trained with a <span acronym-label="FFNN" acronym-form="singular+short">FFNN</span> and kept fixed during the <span acronym-label="LSTM" acronym-form="singular+short">LSTM</span> training in while we train them together with the <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span> layers. To be fair, it should be noted that the wav2vec features might benefit from a system combination effect as parameters trained by the authors of are used in our experiments.

# Conclusion

We apply learnable feature extractors, namely wav2vec and supervised convolutional features, in a hybrid <span acronym-label="BLSTM" acronym-form="singular+short">BLSTM</span>/<span acronym-label="HMM" acronym-form="singular+short">HMM</span> <span acronym-label="ASR" acronym-form="singular+short">ASR</span> system and show their suitability for this type of model. Using a pre-trained wav2vec module helps, however, it does not outperform the non-trainable features and features trained only with a supervised loss in a setting without additional untranscribed data. It is demonstrated that an existing <span acronym-label="AM" acronym-form="singular+short">AM</span> trained on Gammatone features can be exploited in a similar way for all features. A combination of Gammatone and wav2vec features as well as leads to the best results outperforming our previous best system by 4 % and 6 % relative on and , respectively.
