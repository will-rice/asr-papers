## 1 Introduction

Many tasks require a large amount of background information to be solved efficiently, but acquiring a huge amount of data is costly.

In several situations, a human trainer can specify generic knowledge about the domain by providing a data simulator, such as a physical simulators, 3D rendering engines and math problem generators. Using such simulator can generate an arbitrary amount of data, that can be treated exactly the same way as standard observations. This simple approach leads to a better estimation of the parameters because it prevents overfitting, but is subject to a strong model bias, because such data generators often generate data that are far from the observed data.

While the idea of generating data is straightforward, it can be hard to come up with generators that are helping to do transfer learning, because there are not realistic. For example, we will show in this paper that the bAbI dialog generator is so simplistic that it does not carry transfer learning to answer questions about real dialog. One solution is add more realistic data, but then their are a lot of parameters to tune, that make the design of a data generator a complex task. One can think of a 3D rendering engine that is mimicking a real environment: it is hard to choose conditions such a lights orientation and objects in the background to be helpful for the training algorithm. In this paper, we show how to reduce the bias of such simulators, by learning automatically their parameters.

## 2 Regularization Based on a Generative Model

The variable $`x \in \mathcal{X}`$ represents the input. The variable $`y \in \mathcal{Y}`$ is the is the output to predict. The goal is to find a prediction rule by learning it from examples $`\mathcal{D}:={\{{(x_{i},y_{i})}\}}_{i = 1}^{n}`$.

Assume there exist a good model family $`\{{{f_{\theta},\theta} \in \Theta}\}`$ to predict $`y`$ given $`x`$, where $`\theta`$ is an element of the parameter space $`\Theta`$. One common issue with flexible probabilistic models is that they often requires a lots of training samples. For example, a nested stacked LSTM is a general purpose sequence prediction model that can potentially work for many NLP problems, and it requires a huge amount of examples to predict long and meaningful output sequences. ^(inline,backgroundcolor=white!20!white)^(inline,backgroundcolor=white!20!white)todo: inline,backgroundcolor=white!20!whitePS: Let’s swap the nested stacked LSTM for an encoder, then we can use that as a baseline for the location data.

However, in many applications, the number of training data is too small or too costly to acquire. We look at alternative ways to regularize the model so that we can get good performances with few data points. One way is to use surrogate tasks in a transfer learning framework, but finding these surrogate tasks is sometimes difficult. Another way is to use domain knowledge that can partially explain the data.

Let $`p_{\theta}\hspace{0pt}{(\left. y \middle| x \right.)}`$ be the target prediction model. Given the training dataset $`\mathcal{D}`$, the penalized maximum likelihood estimator is obtained by:

```math
{{{{\min\limits_{\theta \in \Theta}\mathcal{L}}\hspace{0pt}{(\theta)}}\quad{where}\quad{\mathcal{L}\hspace{0pt}{(\theta)}}}:={{- {\sum\limits_{i = 1}^{n}{{\log p_{\theta}}\hspace{0pt}{(\left. y_{i} \middle| x_{i} \right.)}}}} + {\lambda\hspace{0pt}\Omega\hspace{0pt}{(\theta)}}}},
```

where $`\Omega\hspace{0pt}{(\theta)}`$ is a regularizer that prevents over-fitting, and $`\lambda \in {\mathbb{R}}`$ the regularization parameter that can be set by cross-validation. Instead of using a standard regularizer, such as the squared norm or the Lasso penalty, we propose in this paper to use a generative model to regularize the estimator.

#### Domain knowledge

A natural way to inject background information is to define a generative model that simulates the way the data are generated. In text understanding applications, such generative models are common such as probabilistic context-free grammars (PCFG) and natural language generation frameworks (e.g. SimpleNLG). Let $`p_{\gamma}\hspace{0pt}{(x,y)}`$ be such a generative model parametrized by a continuous parameter vector $`\gamma \in \Gamma`$. One important difference between the discriminative and the generative probability distributions is that the inference problem of $`y`$ given $`x`$ might be intractable¹¹1Even if tractable, the inference can very costly: for example, PCFG decoding can be done using dynamic programming and has a cubic complexity in the length of the decoded sentence, which is still too high in some applications with long sentences. for the generative model, even if the joint model can be computed efficiently.

In this work, we use the following regularizer:

$`\Omega\hspace{0pt}{(\theta)}`$$`:=`$$`{{\min\limits_{\gamma \in \Gamma}{\mathbb{E}}_{p_{\gamma}\hspace{0pt}{(x,y)}}}\hspace{0pt}\left\lbrack {{{\log p_{\gamma}}\hspace{0pt}{(\left. y \middle| x \right.)}} - {{\log p_{\theta}}\hspace{0pt}{(\left. y \middle| x \right.)}}} \right\rbrack},`$

This regularizer makes intuitive sense as it corresponds to the Kullback-Leibler divergence between the generative and discriminative models. We can see that if the generator $`p_{\gamma}`$ is close to the distribution that generate test data, the method can potentially give good performance. However, in practice, $`\gamma`$ is unknown and difficult to set. In this work, we focus on several techniques that can be used to estimate the generative parameter vector $`\gamma`$ on the training data, making the regularizer data-dependent.

The overall learning objective can be written as:

$`{\min\limits_{{\theta \in \Theta},{\gamma \in \Gamma}}\mathcal{L}}\hspace{0pt}{(\theta,\gamma)}`$

where $`\mathcal{L}\hspace{0pt}{(\theta,\gamma)}`$ is:

$`{{- {\sum\limits_{i = 1}^{n}{{\log p_{\theta}}\hspace{0pt}{(\left. y_{i} \middle| x_{i} \right.)}}}} - {\lambda\hspace{0pt}{\mathbb{E}}_{p_{\gamma}\hspace{0pt}{(x,y)}}\hspace{0pt}\left\lbrack {{{\log p_{\theta}}\hspace{0pt}{(\left. y \middle| x \right.)}} + {{\log p_{\gamma}}\hspace{0pt}{(x)}}} \right\rbrack} - {\lambda\hspace{0pt}\mathcal{H}\hspace{0pt}{(p_{\gamma})}}}.`$

This objective can be viewed as a Generative-Discriminative Tradeoff estimator (GDT) that smoothly interpolates between a purely unregularized discriminative model when $`\lambda = 0`$ and a discriminative model that be closely approximated by a generative model when $`\lambda`$ tends to infinity. Note that when there is no regularization ($`\lambda = 0`$), the parameters $`\gamma`$ and $`\alpha`$ do not need to be estimated as $`\theta`$ does not depend on them.

### 2.1 The GeneRe Algorithm

Equation (4) can be minimized using stochastic gradient descent by sampling a mixture distribution with two components: the empirical data distribution and the sampled data points generated by the data simulator. Their respective proportions are $`\frac{1}{1 + \lambda}`$ and $`\frac{\lambda}{1 + \lambda}`$, respectively. We give the pseudocode in Algorithm 1. It is called GeneRe for _Generative Regularization_.

GradientStepFunction$`\in {\{{VanillaSGD},{Adam},{Adagrad},{orRMSProp}\}}`$

for $`t = {1,2,\cdots}`$ do

     $`{x,y} \sim {{\frac{1}{1 + \lambda}\hspace{0pt}\hat{P}} + {\frac{\lambda}{1 + \lambda}\hspace{0pt}P_{\gamma}}}`$

     $`g_{\theta}\leftarrow{{{\nabla_{\theta}\log}p_{\theta}}\hspace{0pt}{(\left. y \middle| x \right.)}}`$

#### Generative models: interpretable sampling, intractable inference

Generative modeling is natural because we can consider latent variables that add interpretable meaning to the different components of the model. For example, in NLP we can define the latent variable as being the relations that are mentioned in the sentence.

We could consider two main types of approaches to choose a proper latent variable:

- •
  Discrete data structure: we can use efficient algorithms, such as dynamic programming to do sampling and we can propagate the gradient
- •
  Continuous distribution: having a continuous latent variable enables an easy handling of correlations across different parts of the model.

Is this work, we considered multivariate Gaussian distributions as prior distribution for the latent seed of the generative model. The remain Where $`g`$ is the distribution of the latent seed of the generative model. To enable efficient learning, having access to the gradient information of the generative model is important. Ideally, all the uncertainty is put in the sampling, and we have a deterministic sampler: $`\delta\hspace{0pt}{\{{{f\hspace{0pt}{(z)}} = {(x,y)}}\}}`$, where $`\delta`$ is the indicator function and $`z`$ is a latent variable.

$`{p_{\gamma}\hspace{0pt}{(x,y)}} = {\int_{\mathcal{Z}}{f\hspace{0pt}{(x,\left. y \middle| z \right.)}\hspace{0pt}{dg_{\gamma}}\hspace{0pt}{(z)}}}`$

Note that separating the generative process into a simple random differentiable process and a deterministic non-differentiable process is often possible since we only have to fix the seed and make sure any stochastic decision depends deterministically on $`z`$. Typically, we choose $`g_{\gamma}`$ to be a multivariate Gaussian distribution with mean and covariance parameterized by $`\gamma`$.

#### Why not learn a tractable generative model?

The class of tractable generative models is quite restrictive. It lead to good results for parsing (Slav Petrov PhD), but for end-to-end tasks such as question answering, machine reading and translation, generative models that include some intractable modules would be needed. One such examples is the surface form generator in natural language generation, which gives more natural dialogs when combined with a neural language model.

#### Learning

We use stochastic gradient descent to minimize the global loss $`\mathcal{L}`$ with respect to $`\theta`$ and $`\gamma`$. To obtain meaningful gradient, we use a weighted sampler given by $`g_{\gamma}`$: At iteration $`t`$, we sample a variable $`z_{t}`$ using parameters $`\gamma_{t}`$, and then do a gradient step at position $`(\theta_{t},\gamma_{t})`$.

## 3 Experiments

### 3.1 Illustrative Experiment

In this section, we illustrate how GeneRe can learn to identify the correct generator, when the generator family is a mixture of multiple data generators, only one of them being accurate. Formally, $`p_{\gamma} = {\sum_{k = 1}^{K}{\sigma\hspace{0pt}{(\gamma_{k})}\hspace{0pt}p_{k}}}`$, where $`p_{k}`$ are the data distribution. Only one of this distributions, say $`p_{1}`$, has been used to generate the data.

We checked the the algorithm correctly identifies the correct data distribution, and hence leads to better generalization performances than the model learn without generator.

In this illustrative experiments, we create a simple text-to-equation translation problem, where inputs are equations written in words such as ”compute one plus three minus two”, and outputs are symbolic equations, such as ”X = 1 + 3 -2”. Numbers were varying between -20 and 20, and equations could have 2 or 3 numbers with 2 or 3 operations. We used a 20-dimensional sequence-to-sequence model with LSTM as recurrent units sutskever. The model was initialized using 200 iterations of standard gradient descent on the log-probability of the output. GeneRe was run with 500 iterations, varying the fraction of real samples and generated samples from 0% to 100%. A $`\ell_{2}`$ regularization of 0.1 was used to avoid having zero probabilities. At each iteration, the baseline is updated using a moving average preserving 98% of the previous value, i.e. $`\mu_{t + 1} = {{0.98\hspace{0pt}\mu_{t}} + {0.02 \ast \ell_{t}}}`$. All the experiments were repeated 10 times and a constant learning rate of 0.1 was used.

Results are shown on Figure 1, where the average loss computed on test data is plotted against the fraction of real data used during learning.

We can see the best generalization performances are obtained when there is a balanced mix of real and artificial data.

### 3.2 Aspect-Based Sentiment Analysis

Aspect based sentiment analysis identifies sentiment expressed with regard to a specific aspect and with regard to a specific entity. A given text unit (here a sentence) can express opinion on more than one entity and and on different aspects of each entity. The current release of the dataset is limited to sentences that contain mentions of two locations with a pre-specified list of aspects. Polarity (sentiment) can be positive, negative or none. None indicates that the sentence does not express an opinion for a specific location and aspect. Dataset includes 802 such sentences. Following are examples of input text and output labels:
